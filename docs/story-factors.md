# 短篇结构因子流水线

**招聘阅读：[完整深度案例](story-case.md) · [交互证据实验室](../cases.html#stories)**

2026-10-17 追加只读重审：185 篇源文本哈希一致，3,083 条摘录全部逐字命中，schema 与行号映射问题为 0。详见 [本次报告](../data/story-audit.json)；没有重跑模型提取。

把散落的故事材料整理成可检索的结构记录，并将摘录回指到原文，服务后续的拆解、对标与独立重构。

## 处理链路

```text
原文清点 → 文本清洗与行号 → 分片处理 → 结构化提取
    → 字段与分类校验 → 摘录逐字命中 → 异常修补
    → 冻结已完成批次 → 检索与表格交付
```

记录包括核心伤害、人物动机、主角手段、事件链、情节变化、可复用装置、候选卡点及来源位置。原文自相矛盾时保留备注，避免用推测补圆。

## 检索中的实际发现

历史试用记录中，宽泛的“公开 + 证据”条件命中了 174/185 篇，区分度很低。增加具体物件与利益条件后，范围才能明显缩小。因此展示强调人物利益、行动和兑现链条，而不只做标签堆积。

## 决策卡

| 决策卡 | 内容 |
| --- | --- |
| 用户问题 | 直接存储总结，无法判断结论是否有原文支撑，也不方便继续检索与组合 |
| 目标指标（假设） | 摘录可回查率（当前 3,083 条逐字命中、0 未命中）/ 检索可收窄性（174 → 2）/ 异常可留档（12 篇矛盾备注） |
| 关键取舍 | 不改原文，用阅读副本去重；程序只管形式约束，语义判断留给编辑；信息不足写「文中未明写」，不猜 |
| 复核结果 | 185 篇哈希一致、0 结构问题；不等于语义全部人工复核，也不代表检索准确率 |

以上为设计意图与假设，不是已验证的业务数据。
