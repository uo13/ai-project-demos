花令 Agent：把档案选择与工具执行变成可验证的契约

打开证据实验室 · 公开产品入口 · Agent 原始快照复查 · 候选守卫复查

30 秒项目摘要

花令是围绕用户档案提供主题对话和文化娱乐内容的 AI 产品。难点不仅在于模型回答什么，还在于它调用工具时使用哪个档案、参数错误后如何恢复、什么时候应明确宣告失败。

既有资料确认邵保瑞在项目中承担产品与全栈开发。本案例把产品入口、已有实现、定向复查和本次候选改进放在一起展示。协作项目的代码存在性不等于每个模块均由个人独立完成；不据此扩大个人作者范围。

场景与风险：用户选了 B，参数不能来自 A

当用户显式选择某个档案后，模型可能仍给出旧档案 ID、遗漏参数，或在一次回复中调用多个工具。应用需要维护明确的上下文权威来源，避免“回答看起来流畅，工具却使用另一份参数”。

可验收目标是：显式选择进入确定性的参数归一化；工具结果回传模型；缺参重试有上限；未完成的流不能被标记为成功。这里不把命理解释当作科学验证，重点评价软件的上下文一致性与失败处理。

从用户动作到最终回复

用户选择档案 / 发送问题
  → 身份、会话与显式档案上下文
  → 模型返回工具调用（本次测试用合成响应替代）
  → 参数归一化 → 工具执行 → 必要时修复并限次重试
  → 工具结果写入对话 → 下一轮模型回复
  → 完成 / 上游错误 / 空回答 / 超轮数 / 截断未完成

原始代码中的定位点包括 AgentService.run、_normalize_tool_arguments、_execute_tool_with_retry、_normalize_assistant_message 与 _SSELineSplitter。报告记录两个源文件的 SHA-256，私有源码不随作品集公开。

关键取舍一：统一入口，保留不同运行时

玩法广场原有三种配置来源。历史审计记录的问题是：外部玩法被送入内置测试配置查询，得到空配置，入口断裂。

已有方案用一次 resolveUnifiedPlayDefinition(slug) 解析出原配置与运行时，再分别送入 PlayEngine、TestEngine 或外部组件。它统一了注册、路由和详情外壳，没有宣称底层题目模型、计分和状态管理已经合并。

对比点原问题已有实现
配置查找入口与详情重复查询，来源约定可能不一致单一解析结果向下传递
外部玩法在错误的配置源中再次查找按 runtimeKind 分发到外部组件
重复 slug同名来源存在覆盖歧义明确来源优先级并验证重复项
非法入口随意猜测默认配置会隐藏错误不存在的 slug 返回空结果

2026-10-17 从原始项目归档中恢复完整前端配置，实际重跑原有 21 条断言：21/21 通过，67 个唯一 slug 可解析。三类原始数量分别为 37、30、3，重复 slug 为 3 个。完整结果

这只证明配置解析；不等于 67 个玩法均已端到端验收。历史材料仍记有 84 个 TypeScript 错误及部分后端联调待办，本次没有重跑全站构建或抹去这些限制。

关键取舍二：失败状态属于产品契约

本次执行原始 Agent 服务与工具基础类型，将配置、日志等应用依赖替换为隔离边界；模型轮次与工具返回使用合成夹具。没有使用真实用户档案、数据库或付费接口。

检查原始快照结果能证明的内容
H01 未配置服务通过返回明确失败状态
H02 一轮两个工具通过执行、回传后在第二轮结束
H03 缺少日期通过第一次失败后提取日期，第二次执行成功
H04 上游错误通过不标记为完成
H05 工具循环通过达到轮数限制后停止
H06 续写耗尽通过保留 length_exceeded
H07 空回答通过重试仍为空后明确失败
H08 显式单档案覆盖错误 ID通过使用选中档案
H09 原始 reasoning 字段通过不进入规范化助手消息
H10 中文 SSE 单字节切片通过UTF-8 字符未损坏
H11 多档案参数一致性失败第二个 ID 与第一个档案参数并存
H12 仅 ID 查询失败已移除的旧出生信息被后续回退再次注入

原始快照为 10/12 通过。 这是定向回归的覆盖结果，不是线上成功率、模型准确率或大样本质量评分。

失败复盘与候选改进

H11 的原因是选中列表里保留了第二个档案 ID，但出生信息注入仍固定使用第一个档案。H12 则是早先删除旧参数之后，通用回退逻辑又把它加回。

本次新增外层参数守卫：按最终档案 ID 取得匹配的选中对象；多个档案没有明确选择时拒绝执行；仅按 ID 查询的紫微工具在最后一道边界移除旧出生信息。原输入不被就地修改。

同一组 12 项检查加上候选守卫后 12/12 通过，另有 6 项公开的守卫测试。候选代码在本仓库可运行；它没有合入或部署到花令生产服务。

两处不一致发生在参数层。最终是否计算错档案还取决于执行器是否优先从数据库按 ID 取值；本次不声称已发现线上用户结果错误。守卫也不替代服务端的档案归属、版本和权限验证。

对招聘方可核查的交付

  • 产品公开页面与广场截图，标明观察日期和范围。
  • 原始服务 12 项复查结果、候选守卫同题结果，以及独立可运行的守卫代码。
  • 原有 21 项解析检查的本次执行结果、源文件哈希和历史限制。
  • 浏览器证据回放：逐项查看期望、实际结果和工具事件，不伪装成实时大模型对话。

本次未提供真实服务成功率、留存、营收或节约成本数字。run() 在此快照中返回的 execution_trace 为 None；实验室展示的是实际捕获的工具事件，不称完整生产 Trace。
