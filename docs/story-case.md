## 30 秒项目摘要

内容创作需要查询人物利益、行动方式、情节变化与反转条件。直接保存一堆总结，难以判断其中的结论是否有原文支撑，也不方便继续检索与组合。

这个项目把原文清点、行号保留、分片提取、结构校验、摘录回查和批次冻结连成一条交付流程。**原始池为 522 篇，当前有证据的冻结批次为 185 篇**。它服务于短剧／短篇的拆解与对标，不把已有文章原文直接作为公开作品展示。

链路用提示词驱动模型完成拆解，不训练、不微调模型；产出物是可回查的结构数据，不是一个新模型。

## 业务问题与验收标准

业务输入是混杂的长文本，部分抓取材料包含重复拼接段。模型输出还可能出现：JSON 合法但字段缺失、候选卡点分类漂移、摘录措辞被改写、事件只有标签没有行动与结果、原作自身前后矛盾。

因此验收分为两层：程序负责字段、类型、条数、序号、受控词表、摘录与行号；编辑负责动机、因果、情绪推进和可复用性。程序通过不能替代后者。

## 输入—处理—交付

```text
原文与清单
  → 保存完整源文本与行号
  → 阅读副本省略确认重复的拼接段
  → 分片提取为结构记录
  → schema / 词表 / 序号校验
  → 连续摘录逐字命中与行号回指
  → 异常修补与来源矛盾备注
  → 冻结已完成批次 → 检索与工作簿交付
```

记录覆盖身份锚点、核心伤害、开局钩子、人物弧线、8—14 个主节拍、4—8 个情节变化、结局、回收道具与可复用装置。候选卡点至少四条是当前项目的提取契约，不是所有故事天然应遵守的写作规律。

| 记录部分 | 单篇约束 | 本批次规模 | 可程序化的检查 |
| --- | --- | ---: | --- |
| 身份、伤害、开局与结局 | 固定字段组 | 185 篇各一组 | 必填字段、字段类型、受控词表 |
| 主节拍 | 8—14 个，序号从 1 连续 | 2,269 条 | 条数、序号、节拍类型 |
| 补充节拍 | 与主链分开记录 | 74 条 | 摘录定位 |
| 情节变化 | 4—8 个 | 1,141 条 | 变化类型词表（6 类） |
| 可复用装置 | 独立条目 | 1,620 条 | 必填结构字段 |
| 关键摘录 | 钩子、伤害证据、结尾句与每条节拍关键句 | 3,083 条 | 逐字命中原文、行号映射 |
| 候选卡点 | 每篇至少 4 个 | 含于主节拍 | 卡点类型词表（10 类） |

一张满足契约的记录可以直接在[原创夹具](../data/story-sample.json)中查看；在[证据实验室](../cases.html#stories)里修改它，就能看到验收在哪里拒收。摘录命中只证明“句子在原文里”，不证明“机制判断正确”，后者属于编辑验收。

## 提取与校验是怎么做的

拆解由一份固定任务提示词完成，校验由独立程序完成，两者之间的接口是每篇一个 JSON 文件。

| 环节 | 载体 | 关键约束 |
| --- | --- | --- |
| 提取 | 任务提示词（私有） | 按批次区间领篇，逐篇全文读取；只写盘，不把记录放进回复 |
| 记录 | 单篇 JSON | 逐字摘抄；8—14 节拍且卡点≥4；受控词表；可直接 json.loads |
| 校验 | resume_validate.py | schema、序号、词表 → 摘录定位 → 行号映射 → 候选择一与异常留档 |
| 复核 | 公开只读重跑 | 以只读方式执行既有 schema() 与 audit()，只输出哈希与计数 |

提示词把拆剧工作拆成可执行动作：读清单、取指定编号区间、逐篇读完整原文、忽略开头可能重复的简介块、写盘一个 JSON、只回一行完成清单（回复会被截断）。硬性要求包括：逐字摘抄字段一个字都不许改、不许补；卡点类型不许自造词；信息不足写「文中未明写」，不许猜；每篇独立文件，不许漏篇或合并。

校验程序读入原文与候选记录：先查字段、类型、条数、序号与受控词表；摘录先在原文精确查找，不中再按空白或标点归一化查找，命中后把实际连续原文回写进记录并记下原因，超长则截到契约上限；再用行偏移把命中位置映射回行号。模型写出的简称类别（如「反转」）按别名表归一到标准词；非卡点的卡点类型会被清空。同一篇存在待审、完成、修补多个候选文件时，优先选取问题最少、摘录未命中最少的一份。程序记下的问题与原作自身的矛盾备注分开保存，后者不算模型错误。

程序能拒收的是形式与定位问题；动机是否成立、因果是否通顺、机制是否可复用，仍由编辑通读判断。

## 关键决策一：不改原文，用阅读副本去重

抓取文件中的拼接块可能与后面的分段重复。已有清洗流程保留完整来源和编号底稿，只在阅读副本中省略确认重复的块。这样可以减少模型重复分析，同时保留摘录回查所需的位置。

原清单的 SHA-256 采用移除 BOM、统一换行后的 UTF-8 文本。本次最初按原始字节比较时出现口径差异，核对生成脚本后改为同时保存文本哈希与字节哈希，避免把 Windows 换行差异误判为内容修改。这是本次审计口径修正，不是历史模型效果提升。

## 关键决策二：把“看起来像原文”改成可定位的检查

已有校验器会尝试空白／标点归一化定位，再将实际连续原文回写为摘录，并记录归一化原因。它没有把相似语句直接算作精确命中。

本次重新执行已有 `schema()` 与 `audit()`，逐篇读入当前源文件，另外复核每条摘录是否出现在所报行号范围。原始文件与冻结记录均保持只读。

| 2026-10-17 实际复核项 | 结果 |
| --- | ---: |
| 冻结批次记录 | 185 / 185 |
| 与清单约定一致的源文本哈希 | 185 / 185 |
| 连续摘录逐字命中 | 3,083 |
| 未命中摘录 | 0 |
| 原有 schema 问题 | 0 |
| 摘录行号映射问题 | 0 |
| 本轮新增归一化 | 0 |
| 保留原文矛盾备注的篇目 | 12 |

同时核对到主事件链 2,269 条、补充节拍 74 条、主情节变化 1,141 条、装置记录 1,620 条。装置的条数不等于独立叙事方法的数量。

公开报告提供 185 行匿名账本，每行有源文本哈希、原字节哈希、记录哈希、摘录数和检查结果。它支持私有源文件持有者回查同一版本；公开访问者无法仅凭哈希证明语义判断正确。

## 关键决策三：检索失败要具体复盘

在同一批记录、同样七个分析字段中，重新执行历史关键词条件，组内 OR、组间 AND：

| 需求 | 本次候选数 | 可得结论 |
| --- | ---: | --- |
| 公开场合 + 凭证证据 | 174 / 185 | 条件太宽，难以直接选材 |
| 再加入票根／入场／通行证／门票 | 2 / 185 | 具体物件能缩小候选集合 |
| 清算 + 关系退出 | 23 / 185 | 仍需人工检查行动与因果 |
| 专业能力 + 离开旧关系 | 22 / 185 | 候选不等于相关性标注 |

收窄后保留的匿名编号为 `REC-0013` 和 `REC-0020`。这次改进是人工追加查询条件，不是重新训练模型，也没有证明准确率从某个百分比提高到另一个百分比。

四组条件、关键词与完整候选集合可以在[证据实验室](../cases.html#stories)中逐个切换查看，不需要本地环境。

历史统计还有 1,589 种不同文字表述、其中 1,558 种只出现在一篇。它主要暴露标签措辞分散，不能据此推断叙事机制稀缺或市场热度。

## 从结构因子到创作交付

已有工作流把检索结果用于利益冲突、证据回收和职业重建等机制的独立组合，再进入项目配置、分集节拍、连续性台账、分场写作和编辑修订。下游的配置、节拍与连续性管理另见[短剧生成与质检工作流](drama-workflow.md)；本页只论证链路两端的可回查性，中间工作簿与成稿不随仓库发布。检索产物如何继续用于生成，见[生成质量门槛案例](generation-case.md)：该案例只公开本次原创的演示产物，不发布对标库书名、正文或摘录。

本次公开一个新写的短场景与完整结构记录，可在[证据实验室的验收台](../cases.html#stories)当场修改 JSON、注入伪摘录或删除字段，观察验收如何拒收。它不冒充历史 185 篇中的一篇，也没有假称浏览器正在调用提取模型。

公开参考校验器覆盖核心契约和连续摘录，附 7 项 Node 回归测试。原校验器的清洗、补充字段与归一化行为更完整，两者不称完全等价。

## 结果、限制与下一次评测设计

当前可以证明：已有批次能通过可追溯的结构与摘录验收，查询过宽的问题可重现，公开参考验收器能拒绝有定位信息的错误输入。

当前不能证明：所有分析已人工复核、语料提高了模型能力、检索拥有某个准确率、正文具有商业转化效果或节省了多少编剧工时。

下一阶段若要评估“好不好用”，应另建独立查询集，由编辑标注相关机制和不可用原因，比较固定候选预算下的检索结果，并记录修改轮次和采用情况。这是待执行方案，不写成当前成果。

## 招聘方如何核查

- 在[证据实验室](../cases.html#stories)查看真实批次的 185 行匿名账本与四组候选集合。
- 下载[审计报告](../data/story-audit.json)、[核心契约](../data/story-record.schema.json)和[原创夹具](../data/story-sample.json)，在 Node.js 20+ 下运行公开回归：

```bash
node --test tests/story-contract.test.mjs
```

- 私有源材料持有者按[复现说明](reproduce.md)使用审计工具重跑现有校验器，比较文件哈希。
- 追问“为什么 0 个结构问题仍不能说明故事分析正确”，检验候选人是否能区分可计算约束与编辑判断；更多追问见[招聘阅读指南](recruiter-guide.md)。
